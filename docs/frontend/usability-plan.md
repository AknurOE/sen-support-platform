# План юзабилити-тестирования

| Пункт | Описание |
|---|---|
| **Цель** | Проверить, что родители и специалисты без подсказок выполняют ключевые задачи и понимают режимы видимости и согласия |
| **Что тестируем** | Кликабельный прототип (демо в `/frontend`), позже — реализованные экраны |
| **Участники** | 5 человек: 2 родителя, 2 специалиста, 1 администратор или координатор. Набираем из респондентов опроса, давших согласие на повторный контакт, и по знакомым семьям и центрам |
| **Условия** | Сессия 20–25 минут; смартфон или ноутбук по выбору участника; модератор не подсказывает; запись экрана только с согласия |
| **Когда** | После предзащиты, на прототипе; повторно — на реализованных экранах |
| **Задачи** | 1) Зарегистрироваться и сохранить профиль ребёнка с согласием. 2) Добавить занятие в расписание. 3) Создать запись в дневнике и сделать её видимой только специалистам. 4) Найти, кто смотрел данные ребёнка |
| **Метрики** | Доля успешно выполненных задач; время на задачу; число ошибок и обращений за помощью; оценка по шкале SUS; комментарии |
| **Критерии успеха** | ≥ 80% задач выполнены без подсказки; SUS ≥ 68; ни одной критической ошибки в задаче про видимость и согласие |
| **Базовое решение для сравнения** | Текущий способ: мессенджер плюс таблица или тетрадь. Время и число шагов той же задачи измеряем на респонденте или по его описанию |
| **Фиксация результатов** | Таблица «участник × задача», список проблем с серьёзностью (низкая / средняя / высокая); правки вносятся в прототип и требования |
| **Связь с проверкой безопасности** | Тесты доступности и безопасности интерфейса не дублируют план верификации по безопасности: здесь проверяем только понятность режимов видимости и согласия |
