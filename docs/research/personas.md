# Персоны и пользовательские сценарии

Персоны составлены по результатам исследования пользователей (опрос: родители n = 3, специалисты n = 4, 22–23.10.2026; см. `evidence-to-requirements.md`) и обобщают ответы респондентов. Реальных людей и детей не описывают. После бесед (`interview-plan.md`) персоны будут уточнены.

## Родитель — «Айгерим», 35 лет
- **Цель:** держать расписание, рекомендации и записи о развитии ребёнка в одном месте.
- **Боли (из опроса):** расписание и общение со специалистами в мессенджерах (3 из 3); теряются домашние задания и рекомендации (3 из 3); записи о развитии ведёт только один из трёх.
- **Устройство:** смартфон (3 из 3), ноутбук редко. Интерфейс на русском или казахском с переключателем.
- **Главные задачи:** посмотреть ближайшее занятие; найти рекомендации для дома; решить, кто видит запись; проверить, кто смотрел данные ребёнка.
- **Приватность:** опасается утечек (3 из 3) и того, что запись увидит посторонний (2 из 3). Важность журнала «кто смотрел данные» оценили на 5 из 5 все трое.

## Специалист — «Динара», 29 лет, логопед
- **Цель:** быстро фиксировать наблюдения после занятия и передавать рекомендации родителям.
- **Боли (из опроса):** записи в Excel и Word (по 3 из 4); информация уходит через WhatsApp и Telegram (4 из 4); теряется динамика прогресса и домашние рекомендации; неудобно структурировать прогресс по целям.
- **Устройство:** смартфон (4 из 4) и ноутбук (3 из 4).
- **Главные задачи:** добавить занятие; записать наблюдение за 2–3 минуты; отметить рекомендации для дома; отправить родителю короткий отчёт.
- **Приватность:** часть заметок не должна быть видна родителям (2 из 4); не нужны подробные диагнозы; опасается утечек и доступа посторонних (по 4 из 4).

## Администратор — «Бауыржан», 40 лет, координатор центра
- **Цель:** управлять пользователями и подтверждать специалистов.
- **Задачи:** одобрить специалиста; заблокировать аккаунт; найти пользователя.
- **Приватность:** не видит содержимое дневников.
- **Примечание:** администраторов в опросе не было, персона построена по модели ролей проекта и считается предположением.

## Пользовательские сценарии (user flows)

| № | Роль | Сценарий | Шаги |
|---|---|---|---|
| 1 | Родитель | Регистрация и профиль ребёнка | Главная → Регистрация (роль «родитель») → Профиль ребёнка → отметить согласие → Сохранить |
| 2 | Родитель | Добавить занятие | Расписание → Добавить занятие → заполнить поля → Добавить |
| 3 | Родитель | Запись в дневник с видимостью | Дневник → Новая запись → тип и текст → переключатель «Только специалисты» → Сохранить |
| 4 | Родитель | Проверить, кто смотрел данные | Журнал доступа → период → Применить → просмотр строк, включая попытки без доступа |
| 5 | Специалист | Запись наблюдения после занятия | Вход → Команда или Дневник → Новая запись → Сохранить |
| 6 | Администратор | Подтвердить специалиста | Вход → Панель администратора → найти пользователя → Подтвердить |
